# Священные конвенции pet_engine_v2

Правила, которые нельзя «чинить» и нельзя обходить. Они унаследованы от v1
байт-в-байт и обеспечивают совместимость редактора, игр, форматов и рендера.

## 1. Зеркальный X (mirrored-X)

Мир рендера зеркалит ось X модели:

```
chunkWorld(x, z, w, l) = (-(x - (w - 1) / 2), 0, z - (l - 1) / 2)
```

Причина — вычисление правого вектора камеры в форке:
`right = up.cross(forward)` вместо привычного `forward.cross(up)`. Из-за
этого кадр рендера зеркален относительно модели.

Следствия, которые нельзя убирать:

- билборды несут зеркало `diag(-1, 1, 1)`, чтобы текст не отражался;
- намотки граней компенсируют зеркало (`quadFlipFor` и соседние правила);
- привязка к граням возвращает центры в кадре рендера
  (`x' = 2 * anchor.x - x`).

Правило: **никогда не «исправлять» lookAt и не снимать зеркало**. Все
координатные переходы выполняются функциями движка
(`chunkWorld`, `modelXFromWorld`, `modelZFromWorld`), а не в приложениях.

## 2. Две системы координат

- **Координаты модели** (`model_v1`, редактор): `x`/`z` — клетки сетки,
  `y` — высота основания, `rotY` — градусы. Так сцена сохраняется в JSON.
- **Мировые координаты** (рендер, камера, навигация, попадания): зеркальный
  кадр из раздела 1.

Правила:

- ноды документа (`ModelNode`) принимают координаты модели; для мировых
  есть отдельные методы (`setWorldPlacement`);
- ноды-примитивы (`BoxNode`, `SpriteNode`, ...) живут в мировых
  координатах;
- приложение не пересчитывает координаты вручную — только функциями движка.

## 3. Билборды

- Билборд — вертикальная карточка, разворачивающаяся к камере по
  горизонтальному направлению.
- Ориентация: зеркало X, поворот по рысканию, затем подъём квада.
- Разворот выполняется каждый кадр для всех зарегистрированных билбордов
  (ноды и запечённые спрайты уровней).
- Порядок вершин в шейдерах билбордов зафиксирован: стандартные выходы
  (`v_position`, `v_normal`, `v_viewvector`, `v_texture_coords`, `v_color`)
  объявляются первыми, в порядке обычного материала, затем специфичные для
  спрайта. Нарушение ломает пайплайн Impeller и роняет кадр.

## 4. Форматы

- `project_v1` — проект: `project.json`, `models/*.json`,
  `textures/`, `sprites/`, `3d_models/`.
- `model_v1` — документ сцены: объекты, мета-объекты, свет, материалы,
  группы, поля сцен (`entries`/`front`).
- Легаси `chunk_v1/v2/v3` читается только при импорте и конвертируется в
  `model_v1` (`blocked` → боксы `unpassable`, `meta_pass` → двери).
- Ключ текстуры включает расширение файла (`wallpaper_beige.png`).
  Текстуры берутся из `textures/`, спрайты — из `sprites/`.
- Сериализация без потерь: `toJson`/`fromJson` должны сохранять все поля.

## 5. Ресурсы и источники

- `ProjectSource` — абстракция байтов проекта: папка на диске (разработка)
  или ассеты Flutter (мобильные). Запись в read-only источник запрещена.
- Ассеты Flutter не рекурсивны, поэтому staging выкладывает файлы плоско
  (`models/model_1.json` → `models__model_1.json`), а `manifest.json`
  хранит исходные пути.
- Кэш текстур и импорт glTF живут в ресурсном менеджере; повторная загрузка
  тех же ключей не создаёт новые ресурсы.

## 6. Уровневый слой

- `LevelGrid`/`LevelCell`/`LevelOpening` — клеточная модель уровня;
  проходимость и рёбра выводятся, а не хранятся.
- Явный бокс `unpassable` всегда сильнее неявной проходимости.
- При переносе сцены ссылкой (`kind model`) привязка — центр сетки
  источника: `origin + (size - 1) / 2`.
- Запекание уровней не должно требовать видеокарту на этапе плана;
  аппаратная часть — отдельный шаг.

## 7. Платформы и рендер

- Flutter master через FVM (`.fvmrc`); стабильный SDK не подходит.
- Интерактивный рендер требует Flutter GPU: macOS и физические устройства;
  симулятор iOS не поддерживается.
- Тесты не создают сцену рендера: проверяется логика без GPU.
- Статическая геометрия в играх сливается по материалам
  (`mergeStatic: true`); редактор оставляет раздельные грани для picking.

## 8. Многогранники (`polyhedron`)

- **Вид документа.** `kind: "polyhedron"` хранит `mesh` (индексные вершины и
  плоские грани с дырками) и неоднородный масштаб `scale: [x,y,z]`;
  `dims` для него пуст. Старые виды и `round3` не меняются, поля
  аддитивны — `model_v1` читается и пишется как раньше.
- **Контуры и нормали.** Внешний контур грани обходится против часовой
  стрелки со стороны внешней нормали (нормаль Ньюэлла), дырки — отдельные
  контуры; ориентацию приводит триангулятор. Рёбра/контуры — только
  `faceLoops` (внешний + дырки), без диагоналей триангуляции.
- **UV.** Явные UV контура — финальные координаты текстуры (материал их не
  поворачивает и не тайлит); если их нет, грань проецируется на плоскость и
  работают обычные `stretch`/`tile`/`tileScaleU/V`. Так конвертер карт
  переносит выравнивание текстур без потерь.
- **Точность.** Вершины/UV/масштаб сериализуются с 6 знаками (`round6`),
  позиции — прежние 3. Лимиты модели расширены до 16384×16384×4096, высота
  объектов — −4096..4096: карты 1:1 из WAD помещаются без обрезки. Для
  легаси-моделей (≤64×64×32) клампы, камера, сетка и зум дают прежние
  значения.
- **Оверлеи редактора.** Выделение объектов и граней/вершин — 1 px; рамка
  уровня — 1 px оранжевая (`0xFFFF8A00`); активный элемент жёлтый
  (`0xFFFFD91A`), остальные в группе — голубые (`0xFF35D0FF`).
- **Уровневый слой.** Клеточная модель (`LevelGrid`) не предназначена для
  карт 1:1; многогранник в уровневом слое всегда печётся как
  `BakeMode.node` и не участвует в CSG.
