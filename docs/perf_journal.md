# Журнал производительности pet_engine_v2

Замеры и разбор узких мест. Методика: `scene_editor` собирается как обычное
macOS-приложение (`fvm flutter run -d macos --enable-flutter-gpu
--enable-impeller`) и запускается с `--dart-define=pet.perf.drag=true` —
встроенный харнесс `scene_editor/lib/src/perf_drag.dart` открывает
`projects/Pet/model_2` и шлёт настоящие pointer-события, протягивая ось X
гизмо переноса 60 шагов по каждому виду объекта. Печатает sync (обработчик
события целиком) и frame (до конца кадра) p50/p95; полная пересборка сцены
видна в строках `renderer: rebuild ... (Nms)`, снимки — в
`scene_editor/temp/perf_screenshots/`. Харнесс живёт в репозитории на время
перф-прохода (без видеокарты его работа невозможна: сборка геометрии в
движке идёт через GPU), после закрытия перф-фазы удаляется.

Сцена: `Pet/model_2`, 24 объекта, 9335 частей, 120 нод, текстуры загружены.

## 0. Базлайн (13 сентября 2026, до правок)

`sync` — время обработчика одного шага драга; `frame` — ожидание конца кадра
(упор в vsync/GPU). Медианы по 60 шагам.

| Объект | Вид | sync p50 | sync p95 | frame p50 |
|---|---|---|---|---|
| `obj_6` | куб (стена) | **0.63 мс** | 0.80 | 32.1 |
| `obj_13` | вставка модели (кресло) | **53.6 мс** | 92.4 | 24.4 |
| `csg_1` | CSG-результат | 0.75 мс | 2.73 | 27.7 |
| `obj_4` | спрайт | **53.6 мс** | 90.9 | 23.1 |
| `obj_14` | glTF (кот) | **52.9 мс** | 91.6 | 23.0 |

Полная `ModelRenderer.rebuild`: 49–121 мс на эту сцену (типично 50–60 мс с
загруженными текстурами).

Выводы:

1. **Куб** идёт быстрым путём `refreshObjectTransforms` — 0.6 мс, это норма.
2. **Вставка, спрайт, glTF** пересобирают всю сцену на КАЖДЫЙ шаг драга
   (`editor_scene.dart` `_refreshAfterTransform`: «запечённые» виды вызывают
   `controller.rebuild()` → `ModelRenderer.rebuild`) — 53 мс синхронно, это
   и есть «очень медленное обновление сцен при перемещении».
3. **CSG**: шаг быстрый (0.75 мс), но видимый результат не двигается во
   время драга — `moveExpansion` возвращает операнды (обычные кубы), поэтому
   редактор считает выборку «не запечённой» и обновляет только скрытые ноды
   операндов; результат перестраивается лишь на отпускании. Это баг
   корректности, а не только производительности.
4. Попутно найден баг ввода: `SceneController.hitGizmo` проверял и невидимые
   гизмо — в режиме переноса скрытый гизмо вращения перехватывал клики по
   оси X (исправлено фильтром `visible`, тест в `engine/test/api/gizmo_test.dart`).

## 1. После правок (13 сентября 2026)

Сделано:

- **Трансформационный быстрый путь.** `ModelRenderer.updateObjectTransforms`
  принимает `translated: {elementId: мировой шаг}`: узлы элемента сдвигаются
  приписыванием перевода к текущей локальной матрице — без геометрии, CSG,
  материалов и пересборки. Редакторский `_moveObjects` считает фактический
  (снапнутый) шаг по каждому объекту и передаёт его; для CSG результат
  сдвигается шагом первого операнда (его ноды зарегистрированы под id
  операции). Цепочки билбордов внутри вставок сдвигаются вместе с нодами,
  иначе покадровый разворот возвращал бы спрайты назад.
- **Идемпотентный свет.** `applyLighting` сравнивает подпись конфигурации и
  не пересобирает свет при том же документе; `setShadows`/`setSsao`/
  `setEnvironmentIntensity` — no-op при том же значении. Редактор зовёт
  `_applyLighting` на каждую ревизию — теперь это сравнение строк.
- **Wireframe по перемещённым.** `_refreshWireframes(only:)` обновляет только
  ноды перемещённых элементов (полный проход остался для `rebuild`).
- **Счётчик пересборок.** `SceneController.rebuildCount` — диагностика и
  регрессионный тест: перенос вставки не растит счётчик
  (`scene_editor/test/editor_scene_test.dart`).

| Объект | Вид | sync p50 до | sync p50 после | frame p50 после |
|---|---|---|---|---|
| `obj_6` | куб (стена) | 0.63 мс | 0.49 мс | 32.6 |
| `obj_13` | вставка модели (кресло) | 53.6 мс | **0.44 мс** | 20.1 |
| `csg_1` | CSG-результат | 0.75 мс (не двигался) | 0.71 мс (двигается) | 25.9 |
| `obj_4` | спрайт | 53.6 мс | **0.33 мс** | 19.0 |
| `obj_14` | glTF (кот) | 52.9 мс | **0.34 мс** | 18.6 |

Полных пересборок за время драга — 0 по всем видам (было: одна на шаг у
вставок, спрайтов и glTF). Визуальная проверка: снимки
`scene_editor/temp/perf_screenshots/{before,after}_*` — кресло, CSG-стена,
спрайт окна и glTF двигаются живьём, контур выделения следует за объектом.

Осталось на будущее (не в этом проходе): поворот «запечённых» видов всё ещё
идёт через полную пересборку (перенос — нет); коалесинг pointer-событий до
одного на кадр (sync и так 0.5 мс); инкрементальные оверлеи.
