# Визуальное тестирование pet_engine_v2

Статус: заготовка. Полная методика появится вместе с приложением `demo`
(фаза 3). До этого действует методика v1:
`../../pet_engine/docs/visual_testing.md`.

## 1. Назначение

Визуальная проверка отвечает на вопрос, который не проверяют модульные
тесты: «сцена выглядит правильно на экране». Проверяются загрузка сцен,
материалы, свет, тени, погода, эффекты и отсутствие заглушек вместо
ресурсов.

## 2. Роли

- **Владелец** выносит вердикт по каждому замечанию (кнопка «Баг исправлен»
  в приложении или запись в журнале).
- **Агент** делает снимки, локализует причину, исправляет, записывает
  события `note` и `fixed`.

## 3. Артефакты

- Журнал замечаний — `demo/visual_tests.json` (появится вместе с demo).
- Снимки — `temp/screenshots/` (в git не попадают).
- История замечаний — только добавление записей, без правки прошлых.

## 4. Методика (перенос из v1)

1. Запустить приложение на macOS или физическом устройстве.
2. Открыть проверяемую фичу по диплинку или через интерфейс.
3. Сделать снимок встроенным механизмом (без системного захвата экрана).
4. Проверить кадр: нет ли фуксии (потерянный ресурс), серых заглушек,
   артефактов, пустых областей.
5. Записать результат в журнал; при дефекте — замечание с параметрами
   воспроизведения.

## 5. Реакция на замечание

1. Прочитать замечание и историю.
2. Воспроизвести снимком с теми же параметрами.
3. Локализовать причину: движок, demo или общий форк.
4. Исправить и прогнать проверки затронутых пакетов.
5. Записать событие `note` с объяснением.
6. Повторить снимок и убедиться, что дефект исчез.
