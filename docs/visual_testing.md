# Визуальное тестирование pet_engine

Методика проверки вопроса, который не проверяют модульные тесты: «сцена
выглядит правильно на экране». Проверяются загрузка сцен, материалы, свет,
тени, погода, эффекты и отсутствие заглушек вместо ресурсов.

## 1. Роли

- **Владелец** выносит вердикт по каждому замечанию (кнопка «Баг исправлен»
  в приложении или запись в журнале).
- **Агент** делает снимки, локализует причину, исправляет, записывает
  события `note` и `fixed`.

## 2. Артефакты

- Журнал замечаний — `example/visual_tests.json`.
- Снимки — `temp/screenshots/` (в git не попадают).
- История замечаний — только добавление записей, без правки прошлых.

## 3. Методика

1. Запустить приложение на macOS или физическом устройстве: `cd example &&
   fvm flutter run -d macos --enable-flutter-gpu --enable-impeller`
   (исходники проектов — в `example/assets`, отдельный staging не нужен).
2. Открыть проверяемую фичу по диплинку или через интерфейс.
3. Сделать **встроенный** снимок движковым механизмом
   (`SceneViewport.capture` + `saveScreenshot`); системный захват экрана не
   нужен и в агентской среде не работает.
4. Проверить кадр: нет ли фуксии (потерянный ресурс), серых заглушек,
   артефактов, пустых областей — `analyzePlaceholders`/`analyzeFrameContent`.
5. Записать результат в журнал; при дефекте — замечание с параметрами
   воспроизведения.

Периодичность: после каждой группы фич example и перед переходом к следующей
вехе; при правках движка — хотя бы одна smoke-фича.

## 4. Реакция на замечание

1. Прочитать замечание и историю.
2. Воспроизвести снимком с теми же параметрами.
3. Локализовать причину: движок, example или общий форк.
4. Исправить и прогнать проверки затронутых пакетов.
5. Записать событие `note` с объяснением.
6. Повторить снимок и убедиться, что дефект исчез.

## 5. Ссылки

- Пример реализации захвата и анализа: `lib/src/visual/screenshot.dart`.
- Диплинки и снимки приложения-примера — `example/tool/deeplink.sh`,

  приложение на движке.
